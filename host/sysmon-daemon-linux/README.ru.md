# sysmon-daemon-linux

Демон для Linux: собирает метрики системы (CPU, RAM, сеть, диск,
температура/thermal state) и раз в 500 мс шлёт их по USB CDC-ACM (serial) на
донгл с TFT-экраном ST7789V 240×240. Протокол — текстовый, построчный
(`S3|...`), байт в байт тот же, что у [демона для macOS](../sysmon-daemon/README.ru.md),
так что прошивка не отличает один хост от другого.

Всё, что он читает, лежит в `/proc`, `/sys` и приходит из psutil: **ни одного
подпроцесса и никаких привилегий** — в отличие от macOS-версии, которой
приходится звать `pmset`, `route` и `osascript`.

## Прошивка донгла

Прошивка собирается в GitHub Actions вашего конфиг-репозитория — см. корневой
README. Скачать артефакт, дважды быстро нажать reset на плате (появится диск
**NICENANO**) и скопировать на него `zmk.uf2`.

Донгл выставляет **два** USB-интерфейса: HID (клавиатура/мышь) и serial
(`/dev/ttyACM*`). Демон находит нужный порт сам handshake'ом: шлёт `PING`,
sysmon-порт отвечает `SYSMON1`. Ни VID/PID, ни номер порта значения не имеют.

## Права на порт и ModemManager

Между свежевоткнутым донглом и работающей связью стоят две вещи, и обе
специфичны для Linux:

- **Группа.** `/dev/ttyACM*` принадлежит группе `dialout` (Debian, Ubuntu,
  Fedora) или `uucp` (Arch). Пользователь вне неё получает `Permission denied`
  на каждом порту.
- **ModemManager.** Он опрашивает каждый новый `/dev/ttyACM*` AT-командами и
  держит его открытым несколько секунд — для демона это выглядит как занятый
  порт или как handshake, истёкший по таймауту на том самом порту, который
  должен был ответить.

Вложенное udev-правило закрывает оба вопроса: отдаёт порт пользователю за
консолью (`uaccess` — без возни с группами и без перелогина) и просит
ModemManager не трогать устройство:

```sh
sudo cp 99-zmk-sysmon.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

После этого переткните донгл. Правило написано под VID/PID по умолчанию у ZMK;
проверьте свои и поправьте файл, если они другие:

```sh
udevadm info -q property -n /dev/ttyACM0 | grep -E 'ID_VENDOR_ID|ID_MODEL_ID'
```

Более грубые альтернативы: `sudo usermod -aG dialout $USER` (с перелогином) для
прав и `sudo systemctl mask ModemManager` для второй половины — последнее только
если на машине никто не звонит через модем.

## Установка демона

Нужен Python ≥ 3.9. Из каталога `host/sysmon-daemon-linux`:

```sh
python3 -m venv ~/.venvs/sysmon
~/.venvs/sysmon/bin/pip install -e .
```

Если репозиторий лежит на съёмном диске, а демон планируется запускать через
systemd, ставьте без `-e` (`pip install .`): код скопируется в venv, и юнит
перестанет зависеть от того, подключён ли диск в момент входа в систему. Минус:
после правок пакет придётся переустанавливать.

### Ручной запуск

```sh
~/.venvs/sysmon/bin/python -m sysmon_daemon_linux --verbose
```

Флаги:

| Флаг          | Описание                                                          |
|---------------|--------------------------------------------------------------------|
| `--interval`  | период отправки в секундах (по умолчанию `0.5`)                    |
| `--port`      | конкретный порт (например `/dev/ttyACM0`) — пропустить автопоиск   |
| `--disk-path` | точка монтирования, по которой считается строка DISK (по умолчанию `/`) |
| `--verbose`   | debug-логирование (в stderr)                                       |

Если устройство не подключено или пропало — демон сам переподключается
(backoff 1–5 с), убивать/перезапускать его не нужно.

У `--disk-path` нет аналога в macOS-версии: на Linux интересное свободное место
часто лежит не на `/`. Укажите `/home` или дата-раздел, если считать надо там.

## Автозапуск через systemd

Юнит **пользовательский**, а не системный: root демону не нужен, а user-юнит
наследует сессию, которой принадлежит порт.

1. Поставить юнит — systemd раскрывает `%h`, поэтому, в отличие от plist'а под
   macOS, править файл не требуется:

   ```sh
   mkdir -p ~/.config/systemd/user
   cp sysmon-daemon.service ~/.config/systemd/user/
   systemctl --user daemon-reload
   systemctl --user enable --now sysmon-daemon
   ```

   Если venv не в `~/.venvs/sysmon`, поправьте путь в `ExecStart` (туда же
   дописываются дополнительные флаги, например `--disk-path /home`).

2. Логи и состояние:

   ```sh
   journalctl --user -u sysmon-daemon -f
   systemctl --user status sysmon-daemon
   ```

   `status=203/EXEC` означает, что systemd не нашёл интерпретатор — почти
   всегда это неверный путь в `ExecStart`.

3. Чтобы демон работал и без графического входа (headless-машина или та, к
   которой вы ходите по SSH):

   ```sh
   loginctl enable-linger $USER
   ```

   Учтите: `uaccess` в udev-правиле отдаёт порт только пользователю *за
   консолью*, так что с linger дополнительно нужно членство в
   `dialout`/`uucp`.

Остановить и выключить автозапуск:

```sh
systemctl --user disable --now sysmon-daemon
```

## Откуда берутся числа

| Метрика | Источник |
| ------- | -------- |
| CPU | `psutil.cpu_percent()`, то есть дельты `/proc/stat`, усреднение по всем ядрам |
| RAM | занято = `MemTotal − MemAvailable`, свободно = `MemAvailable` — пара used/available из `free -h` |
| Диск | `statvfs` по `--disk-path`: занято = `(f_blocks − f_bfree) × f_frsize`, свободно = `f_bavail × f_frsize` — столбцы Used и Avail в `df` |
| Сеть | счётчики `/proc/net/dev` через psutil, дифференцированные по интервалу выборки |
| Температура | `psutil.sensors_temperatures()` (hwmon / thermal zones в `/sys`) |
| Тип интерфейса | устройство default-маршрута из `/proc/net/route`, классифицируется по `/sys/class/net` |

Что полезно знать:

- **Температура**: чипы перебираются в фиксированном порядке — `coretemp`
  (Intel), `k10temp`/`zenpower` (AMD), `cpu_thermal`/`soc_thermal` (ARM-SoC),
  `acpitz` последним, — а внутри чипа метка `Package`/`Tctl`/`Tdie` важнее
  показаний отдельных ядер; если такой метки нет, берётся самое горячее ядро.
  Машина без CPU-сенсора (многие ВМ и контейнеры) шлёт `-`.
- **Thermal state** выводится из той же температуры: как доля от порога
  `critical` (или `high`) самого сенсора, если он его публикует, иначе по
  фиксированным полосам (`nominal` до 70 °C, `fair` до 85, `serious` до 95,
  выше — `critical`). Нет температуры — нет и состояния.
- **Диск**: свободное — это `f_bavail`, а не `f_bfree`, поэтому
  зарезервированные под root блоки (по умолчанию 5 % на ext4) свободными не
  считаются. Отсюда used + free меньше размера раздела. Везде десятичные ГБ,
  как в `df --si`.
- **Тип интерфейса**: среди нескольких default-маршрутов побеждает меньшая
  метрика; устройство с `wireless/` или `phy80211/` в `/sys/class/net` — это
  `WI-FI`; туннельное имя (`tun*`, `tap*`, `wg*`, `ppp*`, `ipsec*`,
  `nordlynx*`, `tailscale*`, `zt*`) означает активный VPN и даёт `VPN`; всё
  остальное, что несёт default-маршрут, включая мосты и virtio, — `ETH`. Если
  IPv4-маршрута по умолчанию нет, читается `/proc/net/ipv6_route`.
- Тип интерфейса и данные по диску **кэшируются на ~30 с**, так что цикл в
  500 мс обращается к файловой системе дважды в минуту.

## Протокол S3 (для отладки)

Хост шлёт одну строку на выборку, `\n` в конце, поля через `|`, N/A = `-`:

```
S3|<cpu%>|<ram_used_mb>|<ram_free_mb>|<ram_pressure%>|<net_up_kbps>|<net_down_kbps>|<disk_used_gb>|<disk_free_gb>|<temp_c>|<thermal_state>|<net_iface>
```

| Поле            | Формат                                    |
|-----------------|-------------------------------------------|
| `cpu%`          | целое 0–100 (усреднение по всем ядрам)    |
| `ram_used_mb`, `ram_free_mb` | целые, МиБ (÷1024²)          |
| `ram_pressure%` | целое 0–100 или `-`                       |
| `net_up_kbps`, `net_down_kbps` | КБ/с, 1 знак после точки   |
| `disk_used_gb`, `disk_free_gb` | ДЕСЯТИЧНЫЕ ГБ (÷10⁹), 1 знак после точки |
| `temp_c`        | °C, 1 знак после точки, или `-`           |
| `thermal_state` | `nominal`/`fair`/`serious`/`critical`/`-` |
| `net_iface`     | токен 1–7 симв. из `[A-Z0-9-]` (`WI-FI`/`ETH`/`VPN`) или `-` |

Пример: `S3|23|8432|7952|45|123.4|2048.7|346.3|138.5|58.3|nominal|WI-FI`

S3 заменяет total-поля старых S1/S2 на пары «занято/свободно», так что
`ram_used_mb + ram_free_mb` — это объём установленной памяти. Прошивка
принимает и S1/S2 (конвертируя total-поля), но демон всегда шлёт S3.
`net_iface`, `temp_c` и `thermal_state` разбираются, но не рисуются — в нижней
половине донгла для них нет места.

Handshake: `PING` → `SYSMON1`. Неизвестные строки прошивка молча игнорирует. Без
пакетов дольше 3 с донгл заменяет значения нижней половины на `--`; верхняя
половина продолжает работать, клавиатура от демона не зависит.

Проверить руками (сначала остановить демона, порт занимает один процесс):

```sh
screen /dev/ttyACM0 115200
# набрать PING и Enter — sysmon-порт ответит SYSMON1
# затем можно вставить строку S3|... из примера выше
# выход из screen: Ctrl-A, затем K
```

## Тесты

Тесты подменяют все внешние входы (часы, счётчики, statvfs, чтение файлов,
сенсоры), поэтому не читают настоящий `/proc` и не открывают порт — и проходят
даже не на Linux:

```sh
~/.venvs/sysmon/bin/pip install -e '.[dev]'
~/.venvs/sysmon/bin/python -m pytest tests/
```
